# 面向收件人的 README 写作

让拿到文件夹的人能够独立找到所需材料、理解主要文件，并识别关键版本和数据含义。按用户指定的交付边界组织内容。

## 先确定交付边界

查看目标目录和现有说明，确认实际会交付哪些文件、读者是谁、最常见的查找任务。

- 用户准备打包一个文件夹时，将该文件夹视为完整的阅读环境。
- 用户需要项目根目录 README 时，再根据任务加入安装、运行、贡献等项目入口。
- 沿用用户指定的语言和文件位置。已有 README 的重写范围由本次请求决定。

内部脚本、配置和日志可以用于核实来源与参数。写入面向收件人的文档时，只保留帮助其查找和理解交付物的事实。

## 从实物建立内容

1. 列出目录、重点文件和主要版本。大量同类文件按用途分组，说明命名规律和代表文件。
2. 读取表头、少量记录、摘要或压缩包文件清单，确认数据内容、单位、矩阵方向和版本差别。
3. 对可能影响使用的来源或处理方法，核实后用一两句说明。字段不明确时，说明已确认的信息；实质性缺口向用户确认。
4. 将读者任务映射到实际入口，例如“查看总览图”“查询单个对象”“获取原始计数”“查看质量报告”。

## 组织文档

按材料规模选用以下内容，合并重复信息：

- 开头说明文件夹装的是什么，以及理解内容所需的最小背景。
- 提供“想找什么、推荐位置、内容或用法”的速查表，优先链接常用文件。
- 当目录结构有助于定位时，添加精简目录树。
- 按用途解释主要文件或同类文件，写清内容和推荐用途；来源只写到足以理解数据的程度。
- 对影响阅读的术语、单位、编码、筛选口径和版本差异作简短解释。

主入口应在文档前部。原始数据、处理后数据、参考材料和历史版本分别标明。详细技术记录可作为补充材料列出，主导览自身应足以完成日常查找。

## 保持文件夹可移交

- 文件链接使用相对于 README 的路径，且目标位于交付根目录内。子目录 README 可以链接交付范围内的上级文件。
- 省去作者机器上的绝对路径、用户名、主机信息及仅在作者环境可用的依赖。
- 包外源码、环境配置和运行日志可以用于核实事实；交付导览以包内可访问的文件为入口。
- 阅读与查找类 README 以文件入口和简短使用提示为主。只有用户需要操作教程，或文件的使用确实依赖操作步骤时，才加入命令。
- 需要命令时，以解压后的目录为起点，写清所需工具，使用随包文件。移交缺少必要材料时，明确指出具体缺项并向用户确认补充范围。
- 编辑范围以文档为主。移动数据、增加交付文件、改名、重新分析、提交或发布均按用户授权执行。

## 写作风格

使用与领域相称的准确表达，直接陈述内容、方法、发现及适用范围。

- 用肯定句说明文件包含什么、测量什么和支持什么用途。
- 删除附带的防御性否定和重复解释，例如事实已经清楚后再加“这不表示……”或“这不是……”。
- 保留有科学意义的阴性结果和必要的方法限制，紧贴相关数据简洁表述。
- 对易混概念，直接写明各自含义。例如“文件 A 的位置单位为 Mb，文件 B 为 bp”。
- 以查找任务决定篇幅。少写工作经过、内部实现细节、复现命令和作者操作环境。
- 说明性文件按功能解释，历史材料按版本解释；同一事实集中写一次。

例如，将“某文件是按样本汇总的结果，不表示所有样本均通过检查”改为“该文件汇总各样本的检查状态，详细指标见同目录质量表”。只有存在对应质量表时才写出这个入口。

## 验证后交付

把目标文件夹视为已复制到另一台机器的独立目录，检查：

- 所有文件链接在交付范围内可解析，文件名与实际内容一致。
- 每个主要子目录都有说明，推荐入口足以覆盖读者的主要查找任务。
- 示例、单位、编码、数量和版本说明与实物一致。
- 文档对作者环境的依赖已消除，保留的命令或教程符合用户实际用途。
- 删除重复段落和习惯性的否定尾句后，方法条件及重要阴性结果仍准确。

验证链接时检查解析后的目标，注意符号链接和路径穿越。包含命令时，在独立临时目录验证适当的只读示例；避免复制大型数据或触发生产计算。交付时简要说明文档位置、调整重点和实际完成的检查。
