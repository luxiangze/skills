# 兼容性与故障诊断

## 已验证的历史行为

2026 年 5 月的项目使用 `yuque-tools@2.3.5`，不是 Rust 版 `ytool`。这两者同名但命令和缓存格式不同。以下经验是历史验证记录，不代表新版仍适用；运行前确认实际包版本，不把新的工具替换进同一流程。

- Node CLI 从进程当前目录读取 `yuque.config.json`，`output` 仅通过配置指定。
- 导出器从 `<output>/.meta/cookies.json` 读取登录态；旧输出目录的缓存不会自动用于新输出目录。
- Node 缓存格式为 `{"expired":0,"data":"<private-cookie>"}`，也可能保存字符串数组。旧导入脚本产生 `{"expire_time":123,"cookies":"<private-cookie>"}`；包装脚本将后者转换成前者。
- 该版本缓存判断是反向的：`expired < Date.now()` 进入复用分支。设置 `0` 只是选择缓存分支，不说明服务端 Cookie 有效，也不能延长真实会话期限。
- 不要复制旧 `booksinfo.json`：它可能让新导出沿用过期索引。只导入必要 Cookie，让导出器重新获取目录。
- 账号密码 API 曾返回 HTTP 400。失败后检查登录态或使用用户私下提供的新 Cookie，不无休止重试密码。

## 失败与完整性

登录失败、HTTP 401/403、登录页 HTML、验证码或 Cookie 失效：停止重复导出，报告需要恢复登录态。不得把返回的 HTML 当成 Markdown 成功。

HTTP 404：可能是文档删除、链接变化、权限隐藏或接口兼容问题，不能仅凭状态码断言已经删除。对保留下来的失败记录核查实际页面或接口。

“非Markdown类型文档”：可能是表格、画板、文件或目录节点。Markdown CLI 无法涵盖所有内容类型；仅在用户要求时制定另一种导出方式。附件仍是远程链接，不额外下载附件，也不承诺离线完整。

全量目录可能出现重复文档索引、同名路径覆盖。`markdown_documents` 是磁盘文档数量，`report_failure_records` 是报告行数，两者不是远端唯一文档的成功数和失败数。要求完整性审计时，需要读取当前版本目录元数据，按文档 ID 或规范 URL 对账，并检查同一路径映射多个 ID；不要猜测元数据结构。

## 脚本返回值与隐私

- 导出模式 `0`：进程返回 0，存在文档与报告，静态检查没有已识别异常；仍未证明完整。
- 导出模式 `1`：输入、访问、进程失败，或缺少文档/报告。
- 导出模式 `2`：已有可用输出，但报告失败、空文件、缺失本地图片或本地图片文件需要核查；保留结果，不自动重跑覆盖。
- `--validate-only` 使用相同的本地审计判定：缺少文档或报告返回 1，发现已识别异常返回 2；返回 0 仍不能证明远端清单完整性。

配置、Cookie、新建输出根目录和 `.meta` 使用私有权限。已有备份的原权限不改写。导出内容、`.meta`、终端记录可能含私有信息；共享技能目录不包含这些内容。临时配置在正常结束或异常退出上下文时清理，强制杀进程或断电可能遗留临时目录，届时按确切路径清理。

脚本检查行内 Markdown 图片和链接；嵌套括号、引用式链接、HTML 图片等复杂语法可能漏检。图片文件统计覆盖常见后缀，不是文件内容鉴定。严格验证时补充对应解析器和实际文档类型的检查。
